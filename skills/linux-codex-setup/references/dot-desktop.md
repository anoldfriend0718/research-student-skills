# 可选：Dot连接Linux服务器

仅在用户要求Dot个人电脑接入时使用。先阅读[官方电脑连接说明](https://learn.chatgpt.com/docs/dots/computers-and-apps)，检查当前桌面平台支持、账号能力及真实授权界面。桌面可运行不等于所有电脑控制功能均支持。

## 设备路径

- 优先目标系统上受支持的官方桌面安装。CLI的SSH连接、CLI remote control、Dot云端电脑、Dot连接的个人电脑是不同能力。
- 原生桌面不兼容而用户确需接入时，先解释条件，评估隔离环境；不要为桌面升级科研宿主glibc。案例主机容器是已验证的特定方案，不是官方对旧CentOS的支持承诺。
- 隔离桌面默认使用独立持久home，不直接挂载或重新标记整个科研home。必要时用容器内专用SSH身份经服务器loopback访问宿主，严格验证host key并限制该key的来源和转发。保留旧authorized_keys备份，不导出私钥。
- 图形socket、显示号、Xauthority、UID和SELinux环境需实测。不要复制案例中的`:1`、UID或namespace规则；保留显示认证、rootless及应用sandbox。
- 启动前检查重复实例和挂载。同一应用home只能由一个实例使用；要保留新容器时同步启动服务，不能让服务下次启动旧版本。

## 登录与授权

先完成可审查的安装、网络和界面准备；用户只处理必要的账号认证。登录已被识别但工作区/设备页超时时，查代理和请求路径，不反复退出账号。

设备页面显示在线后，检查真实授权文案。2026-11-01 案例主机的确认框明确说授权会断开其他桌面；该限制应每次结合当前产品与账号复核。若会替换现有设备且用户尚未同意这个影响，说明具体旧/新设备并确认；已明确授权则直接执行。

完成后同时检查新设备可用和旧设备访问状态。旧条目仍显示在线，不等于仍获准执行任务。

## 无Python的最小容器检查

先在实际目标环境中检查可用工具。下面命令不读取凭据或科研文件；若工具执行器自身还不能启动，这些命令也不会执行。没有Python时不调用Python检查脚本，可通过已授权的独立SSH/容器入口执行这些命令，并明确标注其来源不是Dot任务：

```sh
hostname
id -u
getconf GNU_LIBC_VERSION
for tool in sh python3 bwrap codex ssh; do
  if command -v "$tool"; then :; else printf '%s not-in-PATH\n' "$tool"; fi
done
```

`not-in-PATH`仅说明该进程查找不到，不证明全文件系统不存在。对桌面捆绑依赖应根据真实启动报错或已知安装布局检查，不全盘搜索认证目录。容器和宿主即使用户名、HOME字符串相同，也可能是不同挂载内容；宿主路径须在宿主执行环境中解析。

## 普通隔离执行是单独验收项

案例主机复查曾出现`bwrap is unavailable`，同时提示系统PATH及Codex旁的捆绑位置均未找到bwrap。任务执行器以101退出，用户检查命令尚未执行；此时没有“命令退出码”，只有“工具启动退出码”。此前经正常工具审批成功执行过命令，不能证明普通隔离执行依赖已齐全。

遇到同类问题时，先记录原始错误与执行环境。如果本轮约定遇到审批即停止，就停止并报告，不通过换机器、提权重试或更改安全配置继续。通过独立已授权的只读SSH核验宿主/容器依赖，可以补充安装诊断，但不能冒充原Dot任务执行成功。

修复属于后续安装变更：先核对当前版本期望的依赖位置、容器包状态以及命名空间支持，在对应授权范围内准备修复。仅安装bwrap不自动证明旧内核/嵌套容器兼容；修复后还需验证只读文件确实不能改写，并让原任务环境执行一个普通、无副作用的工具命令。具体见[容器隔离排障与负向验收](bwrap-container.md)。技能不默认执行依赖安装或放宽隔离策略。

若诊断报告约定写在宿主，而任务在启动阶段已失败，应明确“报告未生成，宿主HOME未在该任务中解析”；不能给出猜测路径并声称已保存。

## 真实调用验收

在服务器私有验证目录创建随机非敏感标记，不把期望值预先发送给Dot。只有获得向指定Dot发送消息/执行验证的授权，才让它：

1. 使用已连接的指定设备执行工具，报告实际设备、hostname与用户。
2. 通过已配置的本地宿主入口读取标记和系统/Codex版本，不用Windows或云端scratch替代。
3. 通过宿主CLI运行一次只返回固定短标记的read-only模型请求，报告实际输出和退出码，不启动科研计算。

再由独立SSH通道与原标记逐字比对。结果来自正确机器、工具真正执行和模型调用成功要分别成立。Dot说“连接好了”不足以完成验收。

输入多段消息时检查发送行为：某些UI自动化逐字输入换行会逐段发送。优先使用可可靠填写整个消息的官方工具/界面，或单段明确指令；不要重放含发送的旧脚本。截图只保留相关证据，不读取认证输入或无关私人对话。

## 网络兼容及运行条件

案例主机在同一账号/代理下增加`--disable-http2 --disable-quic`后，工作区和Dot页面恢复并完成调用。它是一次有证据的兼容试验；不默认给所有桌面添加参数，也不据此证明所有超时根因。每次只改一个可核验因素，保留原启动配置。

服务器代理、图形会话和桌面应用需持续运行。oneshot+RemainAfterExit服务的active可能只表示启动步骤完成，应核对容器实际running、设备面板和真实调用；不能当作崩溃恢复能力。整机重启后的图形会话、Xauthority更新、容器重启和授权恢复分别验收，不自动重启科研服务器。
