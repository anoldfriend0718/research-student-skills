# 科研知识库消纳与维护

这是从 `xuqh-researchwiki-steward` 提炼的公开通用版。保留其证据链、知识上提和维护方法，不携带个人知识库、项目注册表、研究成果或工作台路径。现有知识库的规则优先；本技能不假定每个学生已有相同的目录和自动化工具。

## 先确定知识库与任务范围

从当前请求、已配置的环境或用户提供的路径确定 vault 和本次项目。无法确定实际知识库时只询问一次路径，不把当前工作目录自动当成 vault，也不递归搜索个人文件夹。不要自动创建第二个知识库。

读取目标知识库中实际存在的 `AGENTS.md`、首页、项目索引、模板和注册表；沿用其命名、分类、标签和归档规则。没有治理文件时采用 [通用流程](references/ingestion-workflow.md)，不调用不存在的 vault 内部脚本或代理。

只有当前用户明确要求初始化时才创建知识库结构。已有笔记不批量改名、覆盖或移动；原始论文和实验数据保持原样。转换缓存、渲染图、代理报告及一次性脚本留在任务工作区。

## 选择消纳路线

- 学生或自己的 Word 稿件：调用随包的 `$word-to-markdown-academic` 生成工作副本；原 DOCX 与公式/图表结构仍是核验依据。
- 已有 Markdown：优先复用并核对原始来源，不重复转换。
- 外部 PDF/HTML：先建立页码、章节、图表和公式的来源定位。可选用使用者另外安装的全文阅读技能，但它不是本包必装依赖。无法读取全文时只生成明确标注的部分卡，不声称全文消纳完成。
- 自己的已发表论文：区分作者结论、本人角色、原文证据、知识库综合判断；不根据发表状态推断已复现实验或模型。
- 项目任务书、申请书、合同：记录目标、约束与验收要求，不当作性能已经验证的证据。
- 已有项目知识：只更新本次材料影响的论点、方法、主题和缺口，记录支持、冲突、替代或待核查关系。

## 消纳的最小完整链

```text
原始来源 → 来源定位 → 论文/材料卡与证据单元
→ 可复用的论点、方法、主题与缺口 → 项目综合 → 写作证据包
```

读取 [通用流程](references/ingestion-workflow.md)，按任务使用 [论文与证据卡模板](templates/paper-card.md) 和 [写作证据包模板](templates/writing-evidence-packet.md)。不要把每篇文献机械拆成大量空笔记；证据单元先留在来源卡，只有能跨材料复用时才上提。

每个重要证据记录：结论或数据、条件、单位、来源页/图/式/表、支撑对象与不可外推边界。至少保留足以支撑本次目标的证据；缺少证据时明确缺失，不为凑数量虚构三条证据。

在正文中区分 `原文结论`、`本知识库综合判断`、`待核查`、`项目目标` 和 `内部初步证据`。保留反证、不一致结果及适用条件。公式须核对符号、单位、边界条件和适用范围；图片须保留完整图例、坐标与来源定位。

## 连接、上提与维护

正式笔记以自然中文解释“研究什么、为什么做、如何做、得到什么、证据能说明到哪里”，再放审计字段。Obsidian 使用 `[[双链]]` 连接已有概念；遵从知识库实际链接约定，不伪造已存在的笔记。

新材料可以支持、挑战或细化已有笔记。冲突时追加解释和来源，提出合并/退役候选，未经授权不删除旧知识。研究方向和项目规划默认进入候选队列，只有用户要求才写入正式主线。

更新受影响的来源索引、项目首页和日志；材料改变项目论证时同步项目综述、证据空白和待解决问题。不要仅按修改时间判断哪个稿件权威，应查版本说明、状态、交付目录和来源关系。

长批次或用户要求独立审查时，可分配不同材料给不同处理者；每个正式文件只有一个写入者。独立审查应直接读取原始来源及正式输出。工具不支持独立审查时标记 `待独立审查`，不写成 `已验收`；普通单篇消纳无需为了流程额外启动代理。

## 完成核验与报告

按实际范围核对：文件存在、源文件未变、来源定位可追溯、必要 frontmatter 可解析、受影响双链可定位、条件和单位明确、没有把目标写成验证结果。若 vault 自带 lint 工具，只在确认路径和用法后运行。

报告新增或更新的正式笔记、来源依据、实际检查和未解决事项。部分来源不可读、图像尚未核验、只完成索引登记，都要明确说明。未经用户要求不把私有知识库上传到远程仓库。
