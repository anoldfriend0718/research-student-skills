# Word To Markdown Academic

## Core Rule

Preserve the source DOCX. Write only derived Markdown, media folders, backups, and audit outputs. Treat the Markdown as a working copy for polishing, not as validated scientific evidence.

When the manuscript comes from students or collaborators, assume Word styles may be inconsistent. Inspect the actual document structure before deciding whether a block is prose, a real data table, a formula table, or a transparent layout table for figures.

## Multi-Agent Acceleration

Use multiple agents only for long or structurally complex Word manuscripts, especially theses with many formulas, transparent figure-layout tables, mixed media formats, broken captions, or heavy post-conversion audit work. The main thread must first read this skill, inspect the DOCX and target directory, define the canonical output path, backup policy, intermediate-file naming, and final acceptance criteria.

The main thread owns all authoritative decisions and file-changing operations: preserving the source DOCX, creating backups, choosing the final Markdown base, running mutating repair scripts on the canonical file, integrating subagent outputs, and delivering the audited result. Subagents should perform bounded read-only audits or write clearly named candidate reports/manifests/contact sheets inside the output work directory. They must report exact file paths, line ranges, commands run, observed defects, proposed fixes, and unresolved risks.

For formula-heavy manuscripts, split work by semantic scope rather than image number: display equations by chapter, inline symbols/tables as a separate shard, and final QA as read-only. Subagents must output manifest shards only, never edit the canonical Markdown. The main thread merges the shards into one verified manifest, rejects duplicate targets/tags and unverified entries, applies repairs once, and reruns strict audit.

Keep all process files under `<output_dir>/_conversion_work/<run_id>/`. Use subfolders such as `history/`, `formula_sheets/`, `manifests/`, `agents/`, `reports/`, `raw_media/`, and `tmp/`. The output directory root should contain only the final Markdown, `media/`, and `_conversion_work/`. Do not leave `*.before-*.md`, audit reports, formula candidate sheets, manifest shards, or converter logs in the output root.

Recommended parallel division:
- DOCX/OOXML structure agent: inspect `word/document.xml`, relationship files, media order, transparent figure-layout tables, formula-number tables, anchors, and caption proximity.
- Markdown text/math agent: audit converted Markdown for heading hierarchy, citation escapes, inline scientific symbols, display formulas, equation tags, mojibake, and prose wrapping defects.
- Figure/media agent: verify local image links, unresolved `.wmf`/`.emf`/`.tiff`/`data:image` references, duplicated panels, composite-figure candidates, and display-size image needs.
- Table/caption agent: distinguish real data tables, nomenclature tables, formula tables, and figure-layout tables; check table symbols and figure/table caption alignment.

Do not let subagents overwrite the source DOCX, mutate the only canonical Markdown copy, delete raw extracted media, invent formula transcriptions, fabricate citation fields, or silently accept unresolved converter artifacts. Before finishing, the main thread must integrate accepted changes into one canonical Markdown file, rerun the required audits, verify local media existence, inspect representative or user-flagged figures visually, and report unresolved risks explicitly.

## Workflow

1. Inspect inputs and target directory.
   - Confirm the DOCX path, output folder, and desired Markdown basename.
   - Create the output folder if needed.
   - Do not move or overwrite the original DOCX.
   - Create `<output_dir>/_conversion_work/<run_id>/` before any repair pass.
   - Before major repair passes, create a named backup of the current Markdown under `_conversion_work/<run_id>/history/`, not beside the final Markdown.

2. Generate complementary conversions when formulas, figures, or tables matter.
   - Primary text pass: use `markitdown input.docx > output.md` when available.
   - Structure/media pass: use Pandoc with extracted media, for example:

```powershell
pandoc input.docx --extract-media=. -t markdown+tex_math_dollars -o output.pandoc.md
```

   - Use `pandoc` and `markitdown` from PATH. If a Pandoc binary was installed with `pypandoc_binary`, use `python scripts/pandoc_cli.py ...` as a portable command.
   - For a bundled DOCX converter with an explicit output directory, use `python scripts/convert_docx.py INPUT.docx -o OUTPUT.md`. Optional legacy WMF/EMF conversion still requires LibreOffice or a supported image backend.
   - Treat MarkItDown as the prose source, Pandoc as the structure/media source, and DOCX OOXML as the layout authority when multi-panel figures or transparent tables are involved.
   - If MarkItDown output is mojibake-heavy or dominated by `data:image` placeholders while Pandoc preserves readable Chinese text and local media numbering, use Pandoc as the final Markdown base and keep MarkItDown only as a failed comparator.
   - Legacy external converters may return only a short log while still producing converted `.png` files for legacy WMF formulas in the source-side media folder. In that case, treat it as a media-conversion helper, copy only the derived PNGs needed for the output media directory, and do not treat the log as manuscript text.

3. Inspect DOCX structure when Markdown layout looks wrong.
   - If images appear scattered, duplicated, huge, or separated from captions, inspect `word/document.xml` and `word/_rels/document.xml.rels` inside the DOCX.
   - Identify `<w:tbl>` blocks that contain mostly images and empty cells near a `Fig.` caption. These are usually transparent layout tables, not data tables.
   - Recover the original row/cell image order from the table before composing figures.
   - For Chinese theses, treat Word fields such as `_Toc...` and `_Ref...` as conversion residue unless they are intentionally used as stable anchors. Rebuild stable Markdown anchors from visible section, figure, table, or equation numbers instead of leaving `[]{#_Toc... .anchor}` or `[]{#_Ref... .anchor}` in the working copy.
   - Use user screenshots as QA evidence for layout defects, but do not use screenshots as the source of scientific data.

4. Repair media references.
   - If Markdown contains `data:image/...` placeholders, do not assume they are valid base64.
   - Extract DOCX media from `word/media/` into an `assets/` or `media/` folder.
   - Replace Markdown image links with relative local paths.
   - Reject unresolved `image/x-wmf`, `.wmf`, `.emf`, `.tiff`, and `data:image` references in the final working Markdown.
   - Convert `.wmf`, `.emf`, or `.tiff` figure/formula assets to `.png` before final Markdown linking.
   - If WMF formula images remain after conversion to PNG, render or inspect them. Replace verified short symbols and formulas with LaTeX; keep long equation images only as an explicitly reported working-copy limitation when safe transcription is not possible in the current pass.

5. Repair display formulas.
   - Prefer true LaTeX display math over images.
   - Reconstruct formulas from Pandoc output, Word visual inspection, or manual equation reading.
   - When Word stores formulas as legacy OLE/WMF objects, create a formula manifest that maps each formula image target to verified LaTeX and, when present, the equation tag. Keep manuscript-specific formula mappings in the output work directory, not in the global skill instructions.
   - For multi-agent transcription, generate contact sheets and manifest skeletons in `_conversion_work/<run_id>/formula_sheets/` and `_conversion_work/<run_id>/manifests/`; assign subagents disjoint shards and require them to write `formula_manifest.agent-*.json` under `_conversion_work/<run_id>/agents/`.
   - Merge agent shards only after validating that every accepted entry has `status=verified` or `status=accepted`, nonempty `latex`, a valid `kind`, and a unique display `tag`.
   - Preserve the manuscript's equation sequence.
   - Add MathJax-style tags inside display math: `\tag{1}`, `\tag{2}`, etc.
   - For aligned blocks, place the tag after `\end{aligned}`:

```latex
$$
\begin{aligned}
...
\end{aligned}\tag{18}
$$
```

   - Use `scripts/number_display_equations.py` only after confirming the sequence should be numbered by display-block order.

6. Repair inline scientific symbols.
   - Convert Word conversion artifacts such as `k\_{eff}`, `c\_Ca(OH)\_2`, `*T*max`, `*p*eq`, and `$u$is` into proper inline math.
   - Apply the same rule inside Markdown tables. Do not leave table symbols as plain italic fragments such as `*L*1`, `*L*f`, `*delta*f`, `*R*3`, or `*A*`; convert them to `$L_1$`, `$L_f$`, `$\delta_f$`, `$R_3$`, and `$A$`.
   - Use roman subscripts for descriptive labels: `$k_{\mathrm{eff}}$`, `$Q_{\mathrm{rxn}}$`, `$T_{\mathrm{eq}}$`.
   - Preserve variable notation used by the manuscript, but do not leave escaped underscores or italic fragments that break rendering.
   - For common patterns, read `references/cleanup-patterns.md`.

7. Repair encoding, citation, and MathJax hazards before layout polishing.
   - Pandoc may emit numeric citations as `\[1\]`, `\[43, 44\]`, etc. In MathJax-aware Markdown previews these become display-math blocks and make citation numbers float on separate lines. Convert numeric citation escapes back to literal citations: `[1]`, `[43, 44]`.
   - Linked citation groups can have the same defect: `\[[1](#ref-1),[2](#ref-2)\]` is interpreted as a TeX display delimiter and produces KaTeX errors at the `#` anchor. Remove only the escaped outer brackets so it becomes `[[1](#ref-1),[2](#ref-2)]`; preserve every link target and citation number.
   - In reference lists, Pandoc may also emit escaped reference-type markers such as `\[J\]`, `\[M\]`, and `\[C\]`. Convert these to `[J]`, `[M]`, and `[C]` after confirming they are bibliographic type markers, not author text.
   - Search for mojibake and Markdown hazards by code point rather than pasting literal corrupted characters into commands or scripts:

```powershell
rg -n "\\\\\[[0-9, -]+\\\\\]|\\\\\[[A-Za-z]\\\\\]|\\x{922D}\?|\\x{9225}\?|\\x{807D}|\\x{9230}|\\x{951B}|\\x{FFFD}|\\{width=|height=|data:image|image/x-wmf|\\.wmf|\\.emf|\\.tiff" manuscript.md
```

   - Convert only context-verified mojibake. Examples: a corrupted minus sign in `s^...^` may mean `s$^{-1}$`; corrupted degree-C text should become `deg C` or `\u00b0C` in the repaired file; corrupted `mu`, `Omega`, multiplication signs, plus-minus signs, and approximation signs must be inferred from the surrounding unit or equation.
   - When using Python from PowerShell on Windows, do not embed Chinese paths or literal non-ASCII replacement strings in piped scripts if console encoding is uncertain. Run from the output directory with ASCII relative filenames, and construct non-ASCII output with code points, e.g. `chr(0x00B1)`, `chr(0x00B0) + "C"`, `chr(0x03BC)`, and `chr(0x03A9)`. After writing, inspect repaired lines to ensure non-ASCII units were not written as `?` or split into ordinary letters.
   - If a converter splits formula tables into symbol images inside prose, replace short, visually verified symbol images with LaTeX text. Common examples include `mu`, `lambda_l`, `c_p`, `T_m`, `delta`, `dot gamma`, `R_th`, `Pe^*`, and `u_melt`. Keep a long equation as an image only when it cannot be reconstructed safely in the current pass, and remove surrounding table borders and equation-number grid artifacts.

8. Repair prose layout and LaTeX polish.
   - After structural cleanup, unwrap hard line breaks in prose so each logical paragraph is one Markdown paragraph, matching polished academic Markdown style. Preserve blank lines around headings, tables, display math, figures, and captions.
   - Do not join Markdown table rows, image lines, fenced code/math blocks, or consecutive figure panels that must remain separate.
   - Convert Word italic fragments for physical variables into inline LaTeX, including patterns such as `*T*~m~`, `*T*~SS~`, `*u*~r~`, `*u~z~*`, `*R*`, `*F*`, `*Q*`, `*m*`, `*n*`, `*b*`, `*Br*`, `*Ste*`, and `*Pe*` when context confirms they are variables.
   - No short formula or symbol image should remain inside a sentence. Replace it with inline LaTeX, or, if it is a real figure, place it on its own line with the correct caption.
   - For mathematical-model sections, inspect every equation image by contact sheet or visual render and convert reconstructable equations into `$$...\tag{n}$$`. Verify that the equation count and tag sequence match the source manuscript.
   - After formula repair, check KaTeX/MathJax parse hazards in prose: no non-standalone `$$` inside a paragraph, no adjacent inline fragments such as `$a$$b$`, no `$x$<sub>i</sub>` or `*x*<sup>-1</sup>` hybrids, no `***x<sub>i</sub>***`, and no double-subscript patterns such as `c_{\mathrm{p}}_{,s}`. Merge them into one inline formula, for example `$c_{p,s}$`, `$\rho c_p=\epsilon_s\rho_s c_{p,s}+\epsilon_f\rho_f c_{p,f}$`, or `$\mathbf{n}_{p,f}^{*}$`.

9. Repair tables by function, not by converter output.
   - Convert real data tables, nomenclature tables, instrument lists, and uncertainty tables into clean Markdown pipe tables.
   - A pipe table must place its header row before the delimiter row, and every delimiter cell must contain at least three hyphens. Repair `|:--:|:--:|` followed by `| Symbol | Meaning |` into `| Symbol | Meaning |` followed by `|:---:|:---:|`; otherwise the line may render as prose or emoji instead of a table.
   - Remove Pandoc grid-table artifacts such as repeated `+---+` border lines, empty pipe-only rows, and broken wrapped cells.
   - For Word formula-number tables, replace the entire table with one or more display equations and `\tag{}` numbers.
   - For Chinese Word field output, move figure and table anchors to stable IDs such as `fig-3-5` and `tbl-4-1`, then update in-text links to those IDs.
   - For nomenclature tables, preserve paired symbol-definition columns and convert symbols/units to readable inline math.
   - Do not convert transparent figure-layout tables into Markdown tables. Rebuild them as composite figures instead.

10. Recover multi-panel figure layout.
   - When several consecutive image links appear immediately before one `Fig.` or `Fig. S` caption, do not leave them as separate Markdown paragraphs.
   - Compare the caption panel list, the Pandoc/MarkItDown image order, and the DOCX table rows/cells.
   - Generate one composite PNG per multi-panel figure, e.g. `fig06_composite.png`, `figS1_composite.png`, and reference only that composite image in Markdown.
   - Preserve panel order from the DOCX table whenever available.
   - Use common academic layouts:
     - 2 panels: 1x2.
     - 3 panels: 2 on top and 1 centered below, or follow DOCX rows.
     - 4 panels: 2x2.
     - 6 panels: 2x3 or 3x2 according to DOCX rows.
     - Mixed rows: keep logical reading order and reduce blank cells when Word used an empty transparent cell only for positioning.
   - If a single wide image was used as a row-spanning or column-spanning panel, center it at a controlled width instead of stretching it across the full composite.
   - If a source media file is duplicated in a layout table, verify whether it is a true repeated panel or a converter artifact before removing it.
   - Inspect at least the user-flagged figures visually after composing.

11. Trim and size images conservatively.
   - Preserve raw extracted images. Write derived files such as `_trim.png`, `_display.png`, and `_composite.png`.
   - For trimming, use alpha/white-background bounding boxes with generous padding. Do not crop panel labels, colorbar titles, legends, axis labels, units, or caption-like annotations inside the figure.
   - If content is close to an image edge, keep that original edge rather than shaving a few pixels.
   - If a crop removes useful labels, regenerate from the original image with larger padding or use the untrimmed original.
   - For Markdown previews, prefer `_display.png` files over Markdown width attributes. Width attributes are inconsistently rendered across VS Code, Obsidian, GitHub, and Pandoc.
   - Use practical display widths:
     - Single ordinary figures: about 900-1100 px wide.
     - 1x2 or 2x2 composites: about 1200-1400 px wide.
     - Large multi-panel composites: about 1200-1500 px wide, with tall figures made narrower if necessary.
   - Avoid leaving images wider than necessary just because the raw extracted asset is high resolution.

12. Repair headings and manuscript structure.
   - Convert bold pseudo-headings to Markdown headings.
   - Keep section numbers when present: `## 1. Introduction`, `### 2.1 ...`.
   - Fix broken list headings such as `- 1. **Measurement ...**` into actual section headings when context shows they are numbered sections.
   - Keep figure/table captions immediately after the figure/table they describe.

13. Check figures, tables, captions, and citations.
   - Compare the MarkItDown and Pandoc versions around every `Figure`, `Fig.`, `Fig. S`, and `Table` caption.
   - Review every Markdown table header and symbol column for broken math notation, including Pandoc forms such as `*L*~1~` and `*delta*~f~`.
   - Remove duplicate image references introduced by converter artifacts, but do not delete media files unless explicitly asked.
   - Preserve citation markers exactly unless the user asks for citation reformatting.
   - Do not fabricate bibliography fields. Use EndNote/RIS/BibTeX exports only when provided.

14. Validate before finishing.
   - Run `scripts/audit_markdown_conversion.py output.md`.
   - If using a formula manifest, run `scripts/audit_markdown_conversion.py --strict output.md --formula-manifest manifest.json --json-report _conversion_work/<run_id>/reports/audit.json`.
   - If a Chinese thesis still contains Word field anchors, formula-image rows, or raw table border lines, run `scripts/repair_word_layout_markdown.py input.md -o output.md --formula-manifest manifest.json` before the final audit. The manifest should contain only verified formula transcriptions for that manuscript.
   - For regression testing of known-good converted manuscripts, run `scripts/audit_markdown_conversion.py --strict output.md` so warning-level symbol, citation, and layout residues fail the regression instead of being silently accepted.
   - For end-to-end regression, rerun DOCX conversion and compare against a known-good Markdown baseline with `scripts/e2e_docx_regression.py --case NAME DOCX BASELINE_MD --output-dir REGRESSION_DIR`. On Windows, prefer `py -3` or a tool virtual-environment Python instead of the Microsoft Store `python.exe` shim.
   - If fresh converter output fails because of deterministic Pandoc/Word residues, run `scripts/postprocess_markdown_conversion.py fresh.md -o fresh.processed.md --aggressive-symbols`, then audit and compare `fresh.processed.md`. This postprocessor is allowed to repair plain and linked citations, reference-type markers, pipe-table header/delimiter order, image size attributes, grid tables, common italic variable fragments, and `.wmf/.emf/.tiff` image links, but it does not certify formula meaning.
   - When rerunning regression against a known-good latest Markdown, formula-image placeholders may be restored from that baseline with `scripts/restore_formulas_from_baseline.py --fresh fresh.processed.md --baseline latest.md -o fresh.restored.md --allow-unmatched`. Treat this as baseline-assisted regression repair, not as independent formula OCR. Report that provenance explicitly.
   - If a DOCX conversion leaves transparent figure-layout tables as many separate panel images, run `scripts/collapse_figure_image_blocks.py fresh.restored.md -o fresh.figure-collapsed.md` after formula restoration. This script only collapses image-only blocks immediately followed by `Fig.`/`Figure` captions; it does not certify equation or symbol meaning.
   - Treat a fresh conversion with fewer display equation blocks or fewer `\tag{}` markers than the known-good baseline as a regression failure, even if no unclosed math block is present.
   - Verify local images exist.
   - Verify the final Markdown contains no `data:image`, `image/x-wmf`, `.wmf`, `.emf`, `.tif`, or `.tiff` links.
   - Verify the final Markdown contains no escaped numeric citations such as `\[1\]`, escaped reference-type markers such as `\[J\]`, raw Pandoc grid-table borders such as `+---+`, dangling image attributes such as `{width=...}` or `height="..."`, or mojibake sentinels from step 7.
   - Verify the final Markdown contains no escaped linked citation groups such as `\[[1](#ref-1),[2](#ref-2)\]`, no pipe-table delimiter before its header, and no delimiter cell with fewer than three hyphens. The strict audit treats these as failures.
   - Verify the final Markdown contains no ASCII control characters except normal newlines/tabs; failed regex replacements can turn LaTeX such as `\alpha` into BEL-like control characters.
   - Verify the final Markdown contains no KaTeX parse-hazard residues: non-display-line `$$`, `$...$<sub>` or `$...$<sup>`, italic/HTML math hybrids, literal `ParseError` text, or inline double subscripts.
   - Verify display formulas are tagged.
   - Verify that images are standalone figure blocks rather than embedded inside prose, table cells, or captions unless the manuscript intentionally uses an image table.
   - Scan for grid-table artifacts, suspicious inline symbol patterns, and images missing from `media/`.
   - Run `scripts/audit_conversion_workspace.py --main-dir <output_dir> --work-dir <output_dir>/_conversion_work/<run_id> --strict` after moving process artifacts and raw vector media.
   - Visually inspect representative figures after image surgery: at minimum one single figure, one 1x2 figure, one 2x2 figure, and every user-flagged problematic figure.
   - Report unresolved risks explicitly, including any audit warnings known to be false positives.

## Student Word Manuscript Heuristics

- Expect students to use invisible tables for figure layout. Do not trust the converter's Markdown table output for these blocks.
- Expect mixed styles: some captions may be normal paragraphs, some may be bold, and some may be separated from figures by blank paragraphs.
- Expect formula tables: a table with one equation image or OMML formula plus an equation number cell should become a LaTeX display equation with `\tag{n}`, not a Markdown table.
- Expect pasted high-resolution images with excessive white margins. Generate preview-friendly display images.
- Expect figure panels to have inconsistent formats (`.png`, `.emf`, `.tiff`, `.jpeg`) in the same figure. Normalize final links to `.png`.
- Expect converter false positives. Confirm visually or structurally before making destructive cleanup decisions.

## Chinese Project/Application Form Heuristics

Use these rules for Chinese project applications, funding forms, task books, review forms, and other `.docx` documents dominated by merged Word tables and centered form fields.

- Treat the DOCX table structure as the layout authority. These forms often store most content inside merged table cells, including long narrative sections, annual plans, budget tables, signatures, and review opinions.
- Prefer Pandoc GFM/HTML-table output as the final base when MarkItDown preserves readable prose but loses table boundaries, merged cells, check boxes, signatures, or review-form layout. Keep MarkItDown only as a text comparator in that case.
- Remove Pandoc `<colgroup>` blocks and width attributes such as `style="width:..."`, `width=...`, and image `height=...` when they only encode Word page layout. Preserve `text-align: center` for short labels, table headers, dates, signature fields, and other genuinely centered form fields.
- Do not flatten true dense application-form tables into prose unless the user explicitly asks for a plain-text working copy. Preserve `<table>`, `rowspan`, `colspan`, and cell-level alignment for real form grids, budgets, personnel lists, schedules, signature boxes, and review forms.
- Inspect alignment at both paragraph and cell/table levels. In these forms, visually centered content may come from a table cell or header-row convention rather than from each paragraph's `w:pPr/w:jc`. Do not assume paragraph-level OOXML alignment alone captures the rendered layout.
- When Pandoc emits a single-cell narrative table as `<thead><tr><th>...long content...</th></tr></thead><tbody></tbody>` or `<table><tbody><tr><td>...long content...</td></tr></tbody></table>`, check whether the table is merely a bordered content box. For a readable Markdown working copy, remove the outer one-cell table and convert the inner HTML paragraphs to ordinary Markdown paragraphs. Preserve any nested real data tables inside that content.
- When a real form table contains one short label cell plus one wide merged cell containing long narrative prose, such as "project summary", "research basis", "technical route", or "budget explanation", consider extracting the long prose from the table into normal Markdown under the label while keeping the surrounding metadata/form table. This produces a more readable working copy than leaving long prose constrained by a table cell.
- Do not center-align or table-wrap long narrative body cells merely because Word displayed a merged table cell or because Pandoc inferred a header cell. A long paragraph inside a table cell wraps as visually disconnected lines in Markdown/HTML previews. Keep long body prose, literature review, research content, methods, budget explanation, and technical-route paragraphs as normal Markdown paragraphs unless the user explicitly asks for full-form visual fidelity.
- Preserve truly bold section labels with `<strong>` or Markdown bold, but avoid making long body paragraphs bold merely because Pandoc put them in `<th>`. Verify boldness from run/style information or visual evidence before retaining full-cell bold.
- For cover pages and standalone centered body paragraphs such as document titles, dates, "填写说明", and review-list headings, use explicit HTML alignment (`<h1 align="center">...</h1>` or `<p align="center">...</p>`) when ordinary Markdown headings would lose the Word alignment.
- Keep scanned signatures, seals, review pages, and handwritten approval images as local image files referenced from `media/`. Inspect at least one such image visually and do not OCR or rewrite its approval content unless the user explicitly requests it.
- On Windows, avoid embedding Chinese paths directly inside piped Python scripts when console encoding is uncertain. Pass source and output paths through task-specific environment variables and set `PYTHONIOENCODING=utf-8` when printing Chinese diagnostics.
- After cleanup, audit for leftover Word/Pandoc layout residue: raw `+---+` grid borders, `simple_table_border`, `<colgroup>`, dangling width/height attributes, broken bold line artifacts such as `**\`, missing local images, and mojibake or replacement characters.

## Useful Scripts

- `scripts/number_display_equations.py`: add sequential `\tag{n}` to untagged `$$...$$` display equations, or replace existing tags when requested.
- `scripts/audit_markdown_conversion.py`: audit image links, unresolved media, display equation tags, duplicate image refs, KaTeX parse hazards, and common Word-to-Markdown symbol artifacts.
- `scripts/regression_markdown_set.py`: run strict audits and optional Pandoc HTML rendering for multiple known-good Markdown manuscripts, producing one regression report.
- `scripts/e2e_docx_regression.py`: rerun DOCX-to-Markdown conversion for one or more source DOCX files, audit the fresh Markdown, compare it against known-good Markdown baselines, and fail when formulas, media cleanup, citation cleanup, or table-symbol cleanup regress.
- `scripts/postprocess_markdown_conversion.py`: apply deterministic cleanup after Pandoc/MarkItDown conversion, including plain and linked citation unescaping, pipe-table header/delimiter repair, image attribute removal, `.wmf/.emf/.tiff` to `.png` media conversion, Pandoc grid-table normalization, and common inline variable-fragment repair.
- `scripts/repair_word_layout_markdown.py`: repair Word field anchors, escaped Pandoc `_Ref/_Toc` anchors, Chinese section/figure/table captions, formula-number layout tables, inline formula images, raw grid/simple table borders, and real data tables using an optional formula manifest.
- `scripts/formula_gap_report.py`: compare fresh processed Markdown with a known-good baseline, list baseline `$$...\tag{n}$$` blocks, identify likely formula-image locations in the fresh output, generate contact sheets, and optionally write manifest skeleton shards for multi-agent formula reconstruction.
- `scripts/restore_formulas_from_baseline.py`: replace formula-image placeholders in a fresh processed Markdown file with display equations extracted from a known-good baseline. Use only for regression repair or version migration when that baseline is the intended latest Markdown.
- `scripts/collapse_figure_image_blocks.py`: collapse image-only figure layout blocks that are immediately followed by `Fig.` or `Figure` captions into generated composite PNGs, reducing Word transparent-table panel scatter without touching formula tables.
- `scripts/audit_conversion_workspace.py`: verify that process files stay inside `_conversion_work/<run_id>/` and raw `.wmf`/`.emf`/`.tiff` files are not left in the final `media/` folder.

## Completion Criteria

Deliver a Markdown working copy that:

- uses local relative media paths;
- contains no unresolved `data:image`, `.wmf`, `.emf`, `.tiff`, or `image/x-wmf` references;
- preserves formula meaning and equation numbering;
- has readable inline scientific notation in both prose and tables;
- converts real data tables into readable Markdown tables;
- converts transparent figure-layout tables into correctly ordered composite images;
- uses display-size image variants where raw images would dominate the Markdown preview;
- keeps figure/table captions aligned with the right assets;
- leaves the source DOCX and raw extracted media untouched.
